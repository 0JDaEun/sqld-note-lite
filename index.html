JOIN과 결과 행 수

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장JOIN은 조건에 일치하는 행의 조합을 만든다. 같은 키가 중복되면 결과 행 수도 곱해진다.
  1. 01

    키가 같은 A의 m개 행과 B의 n개 행은 보통 m×n개 조합을 만든다.

  2. 02

    LEFT JOIN은 왼쪽에서 일치하지 않은 행을 NULL 확장하여 보존한다.

  3. 03

    외부 조인 후 WHERE가 오른쪽 열을 거르면 NULL 확장 행까지 사라질 수 있다.

시험에서 중요한 이유

결과를 추론하는 문제의 출발점이다. INNER/LEFT의 차이와 ON/WHERE 위치를 동시에 묻기 쉽다.

03 / EXAM TRAPS

헷갈리기 쉬운 조건을 구별해요.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

ON에서 B.tag = 'X'

LEFT에 남는 A.id=1의 NULL 행은 유지. id=2 두 행은 X와 매칭 → 총 3행.

WHERE B.tag = 'X'

조인 완료 후 NULL 행을 제거. id=2 두 행만 생존 → 총 2행.

시험에서 자주 틀리는 지점

LEFT JOIN이라고 해서 WHERE 뒤에도 왼쪽 행이 반드시 모두 남는 것은 아니다. 조건이 ON에 있는지 WHERE에 있는지 확인한다.

시험 직전 다시 볼 3가지
  • 중복 키: m×n
  • LEFT JOIN: 미매칭 왼쪽 행 보존
  • WHERE B.col=값: NULL 확장 행 탈락 가능

NULL과 3값 논리

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장NULL은 값이 없거나 알려지지 않았다는 뜻이다. 비교 결과는 TRUE/FALSE 외에 UNKNOWN이 될 수 있다.
  1. 01

    NULL = NULL도 TRUE가 아니라 UNKNOWN이다. NULL 여부는 IS NULL로 검사한다.

  2. 02

    WHERE는 TRUE만 통과시킨다. FALSE와 UNKNOWN 모두 제거된다.

  3. 03

    NOT IN 안에 NULL이 있으면 일반적으로 조건이 TRUE가 되는 행이 없어질 수 있다.

시험에서 중요한 이유

기존에 혼동했던 NOT IN 함정과 직접 연결된다. SQLD의 결과 예측에서 실점 원인이 되기 쉽다.

03 / EXAM TRAPS

헷갈리기 쉬운 조건을 구별해요.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

NOT IN

NULL 포함 여부에 매우 민감. 제외 목록에 NULL이 있으면 결과가 없어질 수 있다.

시험에서 자주 틀리는 지점

NOT IN을 단순히 “없는 값만 반환”이라고 읽지 말 것. 목록의 NULL부터 검사한다. 단, 빈 목록을 반환하는 서브쿼리는 별도의 경계 사례다.

시험 직전 다시 볼 3가지
  • NULL 비교는 UNKNOWN
  • TRUE만 WHERE 통과
  • NOT IN + NULL → 먼저 함정 의심

GROUP BY와 HAVING

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장WHERE로 개별 행을 거른 뒤 GROUP BY로 묶고, HAVING으로 만들어진 그룹을 거른다.
  1. 01

    COUNT(*)는 그룹의 모든 행, COUNT(col)은 NULL이 아닌 값의 개수를 센다.

  2. 02

    HAVING은 그룹 단위 조건이며 WHERE에서는 집계 함수를 직접 조건으로 쓰지 않는다.

  3. 03

    GROUP BY 없이 집계만 하면 전체를 하나의 그룹으로 계산한다.

시험에서 중요한 이유

COUNT와 SUM 결과 추적, 집계 대상 NULL 처리, 그룹 제거 조건을 한 번에 묻는 문제가 많다.

02 / WORKED EXAMPLE

표로 따라가며 확인해요.

아래 데이터가 주어졌다고 가정한다. 표의 각 행을 따라가며 SQL이 어떤 결과를 만드는지 확인한다.

입력 데이터→SQL 실행→결과 확인

SELECT region, COUNT(*) AS cnt, SUM(amount) AS total
FROM SALES

GROUP BY region

  1. 1

    WHERE amount>=50: A의 NULL 행을 제외해 A 1행, B 2행이 남는다.

  2. 2

    GROUP BY: A와 B 두 그룹을 만든다.

  3. 3

    HAVING COUNT(*)>=2: A는 탈락, B는 생존. B의 SUM은 50+70=120.

03 / EXAM TRAPS

헷갈리기 쉬운 조건을 구별해요.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

WHERE

개별 행을 그룹 만들기 전에 제거한다. amount>=50이 먼저 평가된다.

HAVING

그룹을 만든 이후 제거한다. COUNT(*)>=2로 B만 남는다.

시험에서 자주 틀리는 지점

COUNT(*)와 COUNT(열)의 차이를 놓치면 NULL 포함 그룹에서 오답이 나온다. 입력이 0행일 때 COUNT는 0, SUM은 NULL인 점도 알아둔다.

시험 직전 다시 볼 3가지
  • WHERE → GROUP BY → HAVING
  • COUNT(*) = 행 수
  • COUNT(col) = NULL 제외

윈도우 함수

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장윈도우 함수는 행을 하나로 축약하지 않고, 각 행에 그룹 내 순위·집계·이전 행 등의 값을 추가한다.
  1. 01

    RANK: 동점 뒤 순위 건너뜀. DENSE_RANK: 동점 뒤 순위 연속.

  2. 02

    PARTITION BY는 윈도우 계산 범위를 나누지만 그룹처럼 행을 합치지 않는다.

  3. 03

    Oracle에서 프레임을 생략한 집계형 OVER(ORDER BY)는 기본적으로 RANGE UNBOUNDED PRECEDING~CURRENT ROW다.

시험에서 중요한 이유

RANK와 DENSE_RANK, PARTITION BY, ROWS/RANGE의 차이를 숫자 예제로 직접 계산해야 한다.

NULL 처리·일반 함수

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장함수는 입력값을 어떤 규칙으로 변환하는지 정확히 계산해야 한다. 특히 NULL 대체 함수들은 인자 수와 선택 방식이 다르다.
  1. 01

    NVL(expr, default): expr이 NULL이면 default로 대체(Oracle).

  2. 02

    NVL2(expr, not_null, null): 첫 인자의 NULL 여부에 따라 둘 중 하나를 반환한다.

  3. 03

    COALESCE는 왼쪽부터 첫 번째 NULL이 아닌 인자를 반환한다.

시험에서 중요한 이유

개별 함수 암기 문제와 여러 함수가 겹친 출력 결과 예측 문제에 대응한다.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

NVL / NVL2

NVL은 2인자 대체, NVL2는 3인자 조건 분기다.

COALESCE / NULLIF

COALESCE는 첫 비NULL, NULLIF는 두 값이 같으면 NULL이다.

시험에서 자주 틀리는 지점

Oracle에서는 문자형 빈 문자열('')을 NULL처럼 취급한다. 반면 숫자 0과 문자 '0'은 NULL이 아니다. 함수의 암묵적 형변환에도 유의한다.

시험 직전 다시 볼 3가지
  • NVL(NULL,0)=0
  • NVL2(NULL,A,B)=B
  • COALESCE → 첫 비NULL

TOP-N과 정렬

01 / CORE CONCEPT

먼저, 이 원리를 이해해요.

세 가지 기준을 알면 해당 유형의 문제에서 판단할 근거가 생겨요.

핵심 한 문장상위 N건은 반드시 어떤 순서로 상위인지 먼저 정해야 한다. Oracle ROWNUM과 FETCH의 적용 위치가 다르다.
  1. 01

    ROWNUM은 행이 선택되며 번호가 붙기 때문에 같은 SELECT의 ORDER BY보다 먼저 제한될 수 있다.

  2. 02

    정렬 후 행 제한은 ORDER BY ... FETCH FIRST N ROWS ONLY로 표현할 수 있다.

  3. 03

    WITH TIES는 경계 순위와 같은 정렬 값을 가진 행을 함께 반환한다.

시험에서 중요한 이유

기존 LIMIT/ORDER BY 오답과 연결되지만 DBMS마다 문법과 결과 안정성 판단이 다르다.

03 / EXAM TRAPS

헷갈리기 쉬운 조건을 구별해요.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

FETCH FIRST 2 ROWS ONLY

행 수를 정확히 2개로 제한한다(동점 두 행 중 어느 하나가 포함될지는 추가 정렬키가 없으면 불확정).

FETCH FIRST 2 ROWS WITH TIES

두 번째 행의 정렬 기준 값과 동점인 행을 더 포함하므로 이 예제에서는 3개다.

시험에서 자주 틀리는 지점

WHERE ROWNUM <=2 ORDER BY score DESC를 “전체 데이터의 점수 TOP 2”로 단정하면 안 된다. Oracle에서는 정렬 전에 두 행이 선택될 수 있다.

시험 직전 다시 볼 3가지
  • TOP-N에는 ORDER BY
  • ROWNUM 동일 쿼리 정렬 주의
  • WITH TIES는 N행 초과 가능

핵심 한 문장외부 스키마는 사용자별 관점, 개념 스키마는 DB 전체 논리 구조, 내부 스키마는 물리 저장 구조다.
  1. 01

    외부 스키마: 개별 사용자·응용 프로그램의 뷰.

    개념 스키마: 조직 전체 데이터의 통합 논리 구조.

  3. 03

    내부 스키마: 파일 구조·인덱스 등 물리 저장 방식.

시험에서 중요한 이유

모델링 1과목의 비교형 암기 문제다. 논리적/물리적 데이터 독립성을 반대로 외우는 실수를 피하면 된다.

03 / EXAM TRAPS

헷갈리기 쉬운 조건을 구별해요.

비슷한 표현이라도 어떤 조건이 달라지면 결과가 바뀌는지 비교해요.

논리적 독립성

개념 스키마 변경이 외부 스키마/프로그램에 미치는 영향을 줄이는 성질.

물리적 독립성

내부 저장 변경이 개념 스키마에 영향을 주지 않는 성질.

시험에서 자주 틀리는 지점

내부 스키마의 저장 구조 변경을 논리적 독립성으로 고르면 오답이다. 내부→개념을 보호하는 것은 물리적 독립성이다.

시험 직전 다시 볼 3가지
  • 외부=사용자 관점
  • 개념=전체 논리 구조
  • 내부 변경 보호=물리적 독립성
